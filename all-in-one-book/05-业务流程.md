# 第五章：业务流程

> **本章是全书的核心。** 通过 6 张流程图展示 Kanboard 最关键的业务链路，每张图标注涉及的数据表和关键类名。

---

## 5.1 任务创建流程

> 从表单提交到任务入库、事件触发、自动化执行、通知发送的完整链路。

```mermaid
sequenceDiagram
    participant User as 用户
    participant Ctrl as TaskCreationController
    participant Valid as TaskValidator
    participant Model as TaskCreationModel
    participant DB as 数据库
    participant TagModel as TaskTagModel
    participant Queue as QueueManager
    participant Job as TaskEventJob
    participant Dispatcher as EventDispatcher
    participant ActionMgr as ActionManager
    participant NotifSub as NotificationSubscriber
    participant NotifJob as NotificationJob

    User->>Ctrl: POST 提交任务表单
    Ctrl->>Valid: validateCreation(values)
    Valid-->>Ctrl: 校验通过

    Ctrl->>Model: create(values)

    Note over Model: prepare(): 设置默认值<br/>column_id → 第一列<br/>swimlane_id → 默认泳道<br/>color_id → 默认颜色<br/>creator_id → 当前用户<br/>position → 该列最大值+1<br/>date_creation → now()

    Model->>DB: INSERT INTO tasks [写入 tasks 表]
    DB-->>Model: task_id

    alt 有标签
        Model->>TagModel: save(project_id, task_id, tags)
        TagModel->>DB: INSERT INTO task_has_tags [写入 task_has_tags 表]
    end

    Model->>Queue: push(TaskEventJob)
    Queue->>Job: execute()
    Job->>Dispatcher: dispatch(task.create)

    par 自动化动作
        Dispatcher->>ActionMgr: 已注册的 Action 监听器
        Note over ActionMgr: 检查兼容事件 + 项目匹配<br/>+ 条件满足 → doAction()
    and 通知
        Dispatcher->>NotifSub: handleEvent()
        NotifSub->>Queue: push(NotificationJob)
        Queue->>NotifJob: execute()
        Note over NotifJob: 筛选订阅用户<br/>按偏好渠道发送<br/>(邮件/Web/Webhook)
    end

    Ctrl-->>User: 重定向到任务详情页
```

**要点说明**：
- 任务创建时会自动填充大量默认值（列位置、泳道、颜色、创建时间等），见 `TaskCreationModel::prepare()` 方法
- 事件通过 `QueueManager` 异步推送，`TaskEventJob` 负责实际触发 `task.create` 和 `task.create_update` 两个事件
- Hook 扩展点 `model:task:creation:aftersave` 允许插件在任务创建后执行自定义逻辑

## 5.2 任务在看板上拖拽移动

> 用户在看板上拖拽任务卡片到另一列或另一泳道时的完整后端处理流程。

```mermaid
sequenceDiagram
    participant User as 用户（看板拖拽）
    participant Ajax as BoardAjaxController
    participant PosModel as TaskPositionModel
    participant DB as 数据库
    participant Queue as QueueManager
    participant Job as TaskEventJob
    participant Dispatcher as EventDispatcher
    participant TransSub as TransitionSubscriber
    participant ActionMgr as ActionManager

    User->>Ajax: AJAX POST {task_id, column_id,<br/>position, swimlane_id}
    Ajax->>PosModel: movePosition(project_id, task_id,<br/>column_id, position, swimlane_id)

    PosModel->>DB: startTransaction()

    alt 泳道变更
        Note over PosModel: 场景A: swimlane 改变
        PosModel->>DB: UPDATE tasks SET position=0<br/>WHERE task_id [从原泳道移除]
        PosModel->>PosModel: reorderTasks(原泳道+原列)
        PosModel->>DB: UPDATE tasks SET swimlane_id,<br/>column_id, position [写入 tasks 表]
        PosModel->>PosModel: reorderTasks(新泳道+新列)
    else 列变更（同泳道）
        Note over PosModel: 场景B: column 改变
        PosModel->>DB: UPDATE tasks SET position=0<br/>WHERE task_id [从原列移除]
        PosModel->>PosModel: reorderTasks(原列)
        PosModel->>DB: UPDATE tasks SET column_id,<br/>position [写入 tasks 表]
        PosModel->>PosModel: reorderTasks(新列)
    else 位置变更（同列同泳道）
        Note over PosModel: 场景C: 仅 position 改变
        PosModel->>DB: UPDATE tasks SET position<br/>[写入 tasks 表]
        PosModel->>PosModel: reorderTasks(当前列)
    end

    PosModel->>DB: UPDATE tasks SET<br/>date_moved=now(),<br/>date_modification=now()<br/>[更新 tasks 表时间戳]

    PosModel->>DB: closeTransaction()

    PosModel->>Queue: push(TaskEventJob)
    Queue->>Job: execute()

    alt 列变更
        Job->>Dispatcher: dispatch(task.move.column)
        Dispatcher->>TransSub: 记录转场
        TransSub->>DB: INSERT INTO transitions<br/>[写入 transitions 表]
    else 泳道变更
        Job->>Dispatcher: dispatch(task.move.swimlane)
    else 位置变更
        Job->>Dispatcher: dispatch(task.move.position)
    end

    Dispatcher->>ActionMgr: 触发匹配的自动化动作

    Ajax-->>User: JSON 响应（新看板数据）
```

**要点说明**：
- 整个移动操作在数据库事务中执行，任何失败都会回滚
- `reorderTasks()` 确保同一列/泳道中的所有任务位置连续无间隙
- 列变更会写入 `transitions` 表，这是计算 Cycle Time 和 Lead Time 的数据基础
- 移动事件会触发自动化动作（如"移到 Done 列自动关闭任务"）

## 5.3 任务状态流转

> 任务的打开、关闭、归档状态变化，以及涉及的字段变更。

```mermaid
flowchart TD
    OPEN["打开状态<br/>is_active = 1<br/>date_completed = 0"] -->|"close(task_id)<br/>TaskStatusModel"| CLOSED
    CLOSED["关闭状态<br/>is_active = 0<br/>date_completed = 时间戳"] -->|"open(task_id)<br/>TaskStatusModel"| OPEN

    OPEN -->|"批量关闭<br/>closeMultipleTasks()"| CLOSED
    OPEN -->|"按列关闭<br/>closeTasksBySwimlaneAndColumn()"| CLOSED

    subgraph 关闭操作详情
        C1["1. 更新 tasks 表:<br/>is_active = 0<br/>date_completed = now()<br/>date_modification = now()"]
        C2["2. 关闭所有子任务<br/>UPDATE task_has_subtasks<br/>SET status = 2"]
        C3["3. 触发事件:<br/>task.close"]
        C1 --> C2 --> C3
    end

    subgraph 打开操作详情
        O1["1. 更新 tasks 表:<br/>is_active = 1<br/>date_completed = 0<br/>date_modification = now()"]
        O2["2. 触发事件:<br/>task.open"]
        O1 --> O2
    end

    CLOSED --> 关闭操作详情
    OPEN --> 打开操作详情

    C3 -->|"可能触发"| AUTO1["自动化: 颜色变更"]
    C3 -->|"可能触发"| AUTO2["自动化: 通知发送"]
    O2 -->|"可能触发"| AUTO3["自动化: 重新分配"]

    style OPEN fill:#4CAF50,color:white
    style CLOSED fill:#9E9E9E,color:white
```

**要点说明**：
- Kanboard 的任务状态模型很简单：只有"打开"（`is_active=1`）和"关闭"（`is_active=0`）两个状态
- 关闭任务时会同时关闭所有未完成的子任务
- `date_completed` 在关闭时设为当前时间戳，重新打开时清零
- 没有独立的"归档"状态——关闭即为最终状态，项目级别有归档功能（`projects.is_active=0`）

## 5.4 项目创建流程

> 创建项目时自动初始化默认列、默认泳道和权限的完整事务流程。

```mermaid
sequenceDiagram
    participant User as 用户
    participant Ctrl as ProjectCreationController
    participant Valid as ProjectValidator
    participant ProjModel as ProjectModel
    participant BoardModel as BoardModel
    participant SwimModel as SwimlaneModel
    participant RoleModel as ProjectUserRoleModel
    participant CatModel as CategoryModel
    participant DB as 数据库

    User->>Ctrl: POST 提交项目表单
    Ctrl->>Valid: validateCreation(values)
    Valid-->>Ctrl: 校验通过

    Ctrl->>ProjModel: create(values, userId, addUser=true)

    ProjModel->>DB: startTransaction()

    Note over ProjModel: 设置默认值:<br/>token = ''<br/>last_modified = now()<br/>owner_id = userId<br/>identifier = 大写

    ProjModel->>DB: INSERT INTO projects [写入 projects 表]
    DB-->>ProjModel: project_id

    ProjModel->>BoardModel: create(project_id, defaultColumns)
    Note over BoardModel: 默认列来自用户偏好<br/>通常为: Backlog, Ready,<br/>Work in progress, Done
    BoardModel->>DB: INSERT INTO columns × 4 [写入 columns 表]

    ProjModel->>SwimModel: create(project_id, "Default swimlane")
    SwimModel->>DB: INSERT INTO swimlanes [写入 swimlanes 表]

    ProjModel->>RoleModel: addUser(project_id, userId, PROJECT_MANAGER)
    RoleModel->>DB: INSERT INTO project_has_users [写入 project_has_users 表]

    ProjModel->>CatModel: createDefaultCategories(project_id)
    CatModel->>DB: INSERT INTO project_has_categories [写入 project_has_categories 表]

    ProjModel->>DB: closeTransaction()
    ProjModel-->>Ctrl: project_id

    Ctrl-->>User: 重定向到项目看板
```

**要点说明**：
- 整个创建过程在一个数据库事务中，任何步骤失败都会回滚
- 默认列名可由用户在设置中自定义，通过 `BoardModel::getUserColumns()` 获取
- 创建者自动被设为项目的 `PROJECT_MANAGER` 角色
- 默认分类从全局设置中读取并批量创建

## 5.5 自动化动作触发流程

> 展示一个具体场景：当任务移动到"Done"列时，自动关闭任务。

```mermaid
sequenceDiagram
    participant User as 用户
    participant PosModel as TaskPositionModel
    participant Queue as QueueManager
    participant Job as TaskEventJob
    participant Dispatcher as EventDispatcher
    participant ActMgr as ActionManager
    participant Action as TaskCloseColumn
    participant StatusModel as TaskStatusModel
    participant DB as 数据库

    Note over User: 用户拖拽任务到 Done 列

    User->>PosModel: movePosition(task, done_column)
    PosModel->>DB: UPDATE tasks SET column_id [写入 tasks 表]
    PosModel->>Queue: push(TaskEventJob)

    Queue->>Job: execute()
    Job->>Dispatcher: dispatch(task.move.column)

    Note over Dispatcher: ActionManager 在启动时已<br/>从 actions 表加载规则并注册

    Dispatcher->>ActMgr: 事件通知

    ActMgr->>Action: execute(eventData)

    Note over Action: 检查链:<br/>1. 事件 = task.move.column ✓<br/>2. project_id 匹配 ✓<br/>3. 参数: dst_column = Done 列 ✓<br/>4. 条件满足 ✓

    Action->>Action: doAction(eventData)
    Action->>StatusModel: close(task_id)
    StatusModel->>DB: UPDATE tasks SET is_active=0,<br/>date_completed=now() [写入 tasks 表]
    StatusModel->>DB: UPDATE task_has_subtasks<br/>SET status=2 [关闭子任务]
    StatusModel->>Queue: push(TaskEventJob)

    Note over Queue: 新的 task.close 事件<br/>可能触发更多动作<br/>（递归检测会防止无限循环）

    Queue->>Job: execute()
    Job->>Dispatcher: dispatch(task.close)
    Dispatcher->>ActMgr: 递归检测
    Note over ActMgr: 如果 task.close 已在调用栈中<br/>→ 阻止执行，防止死循环
```

**要点说明**：
- Action 的规则配置存储在 `actions` 表（事件名 + 动作类名）和 `action_has_params` 表（参数如目标列 ID）
- `ActionManager::attachEvents()` 在应用启动时被调用，将所有 Action 注册为 EventDispatcher 的监听器
- 递归防护通过跟踪调用栈中已处理的事件来实现——如果检测到同一 Action 已在执行，则跳过

## 5.6 用户认证流程

> 完整的 Web 登录认证流程，包含 Session 检查、预认证、密码验证、2FA 和暴力破解防护。

```mermaid
sequenceDiagram
    participant User as 用户浏览器
    participant BootMW as BootstrapMiddleware
    participant AuthMW as AuthenticationMiddleware
    participant AuthMgr as AuthenticationManager
    participant RememberMe as RememberMeAuth
    participant DBAuth as DatabaseAuth
    participant LDAPAuth as LdapAuth
    participant TOTP as TotpAuth
    participant AuthSub as AuthSubscriber
    participant DB as 数据库
    participant Session as SessionManager

    User->>BootMW: 请求受保护页面
    BootMW->>Session: open() [读取 sessions 表]
    BootMW->>AuthMW: next()

    AuthMW->>AuthMgr: checkCurrentSession()
    AuthMgr->>AuthMgr: 遍历 SessionCheckProvider
    Note over AuthMgr: DatabaseAuth::isValidSession()<br/>检查用户是否仍然活跃

    alt Session 有效
        AuthMW->>User: 继续处理请求
    else Session 无效
        AuthMW->>AuthMgr: preAuthentication()
        AuthMgr->>RememberMe: authenticate()
        Note over RememberMe: 检查 Cookie 中的 Token<br/>查询 remember_me 表

        alt RememberMe 成功
            RememberMe-->>AuthMgr: UserProfile
            AuthMgr->>AuthMgr: 初始化 UserSession
            AuthMgr->>DB: dispatch(auth.success)
            AuthSub->>DB: INSERT INTO last_logins [写入 last_logins 表]
            AuthMW->>User: 继续处理请求
        else 需要登录
            AuthMW->>User: 302 重定向到 /login
        end
    end

    Note over User: ===== 登录表单提交 =====

    User->>AuthMW: POST /login (username + password)
    AuthMW->>AuthMgr: passwordAuthentication(user, pass)

    AuthMgr->>DBAuth: setUsername(user) + setPassword(pass)
    AuthMgr->>DBAuth: authenticate()
    Note over DBAuth: 查询 users 表<br/>password_verify() 校验

    alt DatabaseAuth 成功
        DBAuth-->>AuthMgr: true
    else DatabaseAuth 失败
        AuthMgr->>LDAPAuth: authenticate()
        Note over LDAPAuth: LDAP bind 验证<br/>同步用户信息到 users 表
        alt LdapAuth 成功
            LDAPAuth-->>AuthMgr: true
        else 全部失败
            AuthMgr->>DB: dispatch(auth.failure)
            AuthSub->>DB: 累计失败次数 [写入 users 表]
            Note over AuthSub: 失败≥3次 → 启用 Captcha<br/>失败≥6次 → 锁定账户
            AuthMgr-->>User: 登录失败
        end
    end

    AuthMgr->>AuthMgr: 初始化 UserSession + UserProfile
    AuthMgr->>DB: dispatch(auth.success)
    AuthSub->>DB: INSERT INTO last_logins [写入 last_logins 表]
    AuthSub->>DB: 重置失败计数 [更新 users 表]
    AuthSub->>DB: INSERT INTO remember_me [写入 remember_me 表]

    alt 用户启用了 2FA
        AuthMgr->>User: 跳转到 TOTP 验证页
        User->>TOTP: 提交 6 位验证码
        TOTP->>TOTP: 校验 TOTP (christian-riesen/otp)
        alt 验证通过
            TOTP-->>User: 认证完成 ✅
        else 验证失败
            TOTP-->>User: 重新输入
        end
    else 无 2FA
        AuthMgr-->>User: 认证完成，跳转目标页 ✅
    end
```

**要点说明**：
- 密码认证按顺序尝试 Provider（先 Database、再 LDAP），第一个成功即停止
- `AuthSubscriber` 负责所有认证相关的副作用：记录登录历史、管理 RememberMe Token、累计/重置失败计数
- 暴力破解防护通过两个阈值实现：3 次失败启用 Captcha（`BRUTEFORCE_CAPTCHA`），6 次失败锁定账户（`BRUTEFORCE_LOCKDOWN`）
- 2FA 验证是独立的后置认证步骤，只在用户启用 `twofactor_activated` 时触发
